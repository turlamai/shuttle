# 共享盘权限自愈证据（icacls (OI)(CI)F）

采集时间：2026-10-27 · 机器：INSZOA2400559（Windows 11，域账号 INNOLIGHT\ren.ji）
位置：`Z:\19 汽车电子事业部\研发部\04_Software\LiDAR\.shuttle-acl-probe`
原始 icacls 输出见同目录 `acl-evidence.txt`。

## 结论

1. **LiDAR 目录本身对 Domain Users 继承的是修改权 (M)**（`INNOLIGHT\Domain Users:(I)(OI)(CI)(M)`）——含删除权。因此在该目录下，即使不做任何授权，新建文件夹也能正常删除。这就是它被选为默认中转目录的原因；也再次印证了「权限问题不是每个目录都有」。
2. **icacls 自授权工作正常**：对传输子文件夹执行 `icacls <dir> /grant "INNOLIGHT\ren.ji:(OI)(CI)F"`（未用 /t）后——
   - 子文件夹立即出现 `INNOLIGHT\ren.ji:(OI)(CI)(F)`（显式 ACE）；
   - 随后创建的 `payload.bin` 自动带 `INNOLIGHT\ren.ji:(I)(F)`（继承的完全控制）。
   这正是 Shuttle 的自愈机制：即使把中转目录换到「RX,W 能建不能删」的公共目录（2026-10-27 实测踩坑），创建者授权后整棵子树仍可正常管理。
3. 授权前后删除均成功（LiDAR 场景前者靠 (M)、后者靠 (F)）；对公共目录场景，授权前删除必然失败、授权后成功——该对比以 2026-10-27 上午在公共目录的实测为准（见团队文档总结）。

## 对 Shuttle 设计的意义

- 自授权不是为 LiDAR 目录准备的，而是**目录可移植性保障**：用户可在设置里把中转目录改到任何有写入权的共享位置，工具行为保持一致。
- 每次发送建子文件夹后立即授权（成本一次 SMB 元数据调用），失败不阻塞传输、只影响远端清理——清理失败走重试 + 通知兜底。
